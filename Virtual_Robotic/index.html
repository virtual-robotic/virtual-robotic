Origen

De la curiosidad al taller entero

Esto no empezó como un plan de negocio: empezó por querer entender cómo se mueve de verdad un brazo robótico, cubo a cubo, hasta que hacer un buen agarre ya no era suficiente y hubo que resolver clasificación, reposición y pedidos como si fuera un taller real.

Virtual Robotic es el nombre que le hemos puesto a ese taller virtual: dos brazos Panda simulados que cogen, clasifican y entregan piezas sin perder ni una, con visión artificial verificando cada agarre — y algo de hardware de verdad metido de por medio, que se explica un poco más abajo.

Y la afición viene de lejos. A mediados de los 80, sin internet y con la revista MicroHobby como manual, el mismo aficionado construyó un brazo de madera con motores de radiocasete, movido con hilos y poleas y controlado por un Spectrum 48K a través del puerto paralelo, programado en FORTH. En 2016 volvió a intentarlo con Arduino, servos y un brazo impreso en 3D. Este proyecto es la tercera vuelta de esa misma afición.

Cómo funciona

Tres piezas de una misma celda

Loader & Sorter

Dos brazos que cogen y clasifican

Un brazo carga piezas en una cinta, el otro las recoge y las clasifica por color. Cada agarre se verifica con visión artificial antes de darlo por bueno — si el brazo cree que tiene una pieza que no tiene, se detecta y se corrige solo.

Cinta y bandeja

Reposición sin intervención

La cinta mueve las piezas y una bandeja (shuttle) las acerca al punto justo de agarre. El puesto de trabajo nunca se queda sin piezas: se repone solo, sin que nadie tenga que estar pendiente.

Panel de pedidos

Almacén y trazabilidad

Cada pieza clasificada avisa al instante a un panel web de pedidos: qué se ha pedido, qué falta fabricar, qué ya está listo y qué se ha entregado ya al cliente, con su albarán numerado y sus importes. Si el panel está apagado la celda sigue funcionando igual, solo que nadie apunta la producción en ningún pedido.

Para quien quiera bajar al detalle

Cómo está hecho

No hace falta saber nada de esto para jugar con el proyecto — es solo para quien le pique la curiosidad técnica, contado con el mismo vocabulario de aficionado con el que lo he ido montando.

Simulación

Webots + ROS 2

Los dos Panda, la cinta y la física de los cubos viven en Webots. ROS 2 conecta todos los nodos Python: cinemática de los brazos, cámaras, control del agarre y el panel de mando.

Visión

Verificación por posición real

No basta con que el sensor de los dedos diga "tengo algo": se comprueba también dónde está de verdad el cubo. Si un cubo se pierde o se atasca, se rescata solo en vez de que el robot siga a ciegas.

Almacén

FastAPI + SQLite

El panel de pedidos es un proyecto aparte que solo habla con la celda por HTTP, con sus propios roles de usuario, un ciclo de pedido en dos etapas (piezas listas y luego repartidas, con albarán) preparado para facturar, y más de 250 tests automáticos que comprueban que el stock nunca se reparte por su cuenta. El catálogo distingue producto, variante (subproducto) y kit (paquete); cada uno puede llevar, si se quiere, un LED de color asociado — es solo decoración para ver de un vistazo qué se fabrica, nunca un requisito para que la producción funcione.

Opcional, no crítico

Dos Raspberry Pi Pico

Una lleva un LED real que indica el color del producto que se está fabricando; la otra, un sensor de proximidad que hace de botón de parada de emergencia. Son un añadido físico, no una pieza del engranaje: si estas dos Pico no arrancan, el resto de la celda funciona exactamente igual.

¿Y entonces para qué están? Pues porque por aquí empezó todo. No tenía un robot de verdad (un brazo como el Panda cuesta un pastón), pero me apetecía tocar algo físico: que lo que pasa dentro del ordenador hiciera algo de verdad, fuera de la pantalla. Así que arranqué con una Pico, un LED y un botón cableados a mano en una protoboard. Cuando el LED se pone del color de la pieza que fabrica el robot simulado, o cuando acercas la mano al sensor y todo se para, se nota que el software está pegado al mundo real. Luego creció todo lo demás y las Pico se quedaron como el puente entre lo virtual y lo físico: el día que llegue un robot de verdad, ya sé cómo enchufarle cosas al ordenador.

Manos a la obra

Juega con él

Con Docker instalado, esto se levanta en tu propio ordenador en un par de comandos. No hace falta tener las Raspberry Pi Pico ni el resto del hardware físico para que funcione.

1 — Levanta el panel de pedidos

# dentro de la carpeta Taller_Administracion docker compose up -d --build

2 — Entra en el panel

Abre http://localhost:8000. Usuario de arranque: admin / admin. Cualquier usuario que crees con rol "normal" también entra con la contraseña 1111, pensada justo para dejar que alguien entre a curiosear sin tener que darle una cuenta propia.

3 — Levanta la celda simulada (opcional)

Es un proyecto aparte que se habla con el panel por red — si solo quieres trastear con pedidos y almacén, con el paso 1 te sobra. Los comandos completos (Webots + ROS 2, dos contenedores) están en LANZAR_PROYECTO.md.

Código

Tócalo tú mismo

Virtual Robotic no vende nada — es un proyecto personal que sigue creciendo pieza a pieza. Todo el código está en GitHub: bájatelo, ábrelo, rómpelo.

Qué necesitas para instalarlo

Linux — donde lo hemos probado

  • Sistema: Linux Mint o Ubuntu 24.04 (también funciona dentro de una máquina virtual con Linux Mint).
  • Docker con Docker Compose v2 (la orden docker compose) y tu usuario en el grupo docker. Más Git para bajar el código.
  • Solo la web de pedidos: con eso te sobra. Ocupa poco más de 0,5 GB.
  • La celda con los robots (Webots + ROS 2): además un escritorio gráfico con X11 y la orden xhost, unos 15 GB de disco libres, 8 GB de RAM o más y internet la primera vez (descarga Webots y sus texturas). Con tarjeta gráfica va fluido; sin ella hay que comentar una línea del docker-compose.yml y va más lento.
Cómo se instala, paso a paso
  1. Abre una terminal e instala Git, Docker y Docker Compose (la última línea es solo para la celda con robots):
    sudo apt update sudo apt install -y git docker.io docker-compose-v2 sudo apt install -y x11-xserver-utils
  2. Para usar Docker sin sudo, añade tu usuario al grupo y cierra la sesión y vuelve a entrar:
    sudo usermod -aG docker $USER
  3. Comprueba que funciona:
    docker --version docker compose version
  4. Baja el código y levanta la web de pedidos:
    git clone https://github.com/virtual-robotic/virtual-robotic.git cd virtual-robotic/Taller_Administracion docker compose up -d --build
    Cuando termine, abre http://localhost:8000 y entra con admin / admin.
  5. Para la celda con los robots sigue LANZAR_PROYECTO.md. La primera vez tarda bastante porque se baja Webots.

Windows

  • Solo la web de pedidos: Docker Desktop (con WSL 2 activado) y Git for Windows. Después docker compose up -d --build y abres http://localhost:8000. Probada en un PC con Windows 10 (2026-09-23).
  • La celda con los robots: funciona en Windows (probado el 2026-09-24 y el 2026-09-26): Webots instalado en Windows y solo ROS 2 en Docker, arrancando con doble clic en arrancar_windows.bat. En un portátil con Windows 11 (Ryzen 7, 30 GB) han trabajado 4 cadenas a la vez para la misma web de pedidos, cada una con su Webots y su panel: crear_linea_windows.bat añade otra y cerrar_windows.bat lo apaga todo. Paso a paso en INSTALAR_WINDOWS.md.
  • Si Docker Desktop no arranca: necesita WSL 2 (si wsl solo muestra su ayuda, hay que activarlo con dism). Con Windows dentro de VirtualBox no funciona: WSL 2 necesita Hyper-V y VirtualBox no soporta Hyper-V anidado (comprobado a fondo: ni con virtualización anidada, 8 GB y 6 procesadores — no expone el bit NPT al huésped). Para probar en Windows hace falta un PC con Windows de verdad. El error 500 Internal Server Error ... dockerDesktopLinuxEngine/_ping solo significa que el motor de Docker no está en marcha: ábrelo y espera a Engine running. En Windows no uses arrancar_todo.sh (es el de Linux): para la web sola, docker compose up -d --build; para todo, arrancar_windows.bat. Todo esto, paso a paso, está en INSTALAR_WINDOWS.md, junto con los robots y las varias cadenas.
Cómo se instala, paso a paso
  1. Docker Desktop: descarga el instalador de Docker Desktop para Windows desde docker.com y déjalo con la opción Use WSL 2 marcada. Reinicia el PC, abre Docker Desktop y espera a que ponga Engine running. Si te dice que falta WSL, abre PowerShell como administrador, escribe wsl --install y reinicia.
  2. Git: instala Git for Windows desde git-scm.com (vale con «Siguiente» a todo).
  3. Abre PowerShell, baja el código y levanta la web de pedidos:
    git clone https://github.com/virtual-robotic/virtual-robotic.git cd virtual-robotic\Taller_Administracion docker compose up -d --build
    Abre http://localhost:8000 y entra con admin / admin.
  4. Para los robots: instala VirtualBox, crea una máquina virtual con Linux Mint (4 procesadores, 8 GB de RAM y 40 GB de disco van bien) y dentro sigue los pasos de Linux. En una máquina virtual normalmente no hay aceleración 3D: comenta la línea /dev/dri como se explica en LANZAR_PROYECTO.md.

Todo lo demás (Python, FastAPI, ROS 2, Webots…) va dentro de los contenedores: no hay que instalarlo a mano. Las Raspberry Pi Pico son opcionales (un cable USB y Thonny). Empieza siempre por la web de pedidos: la sección «Juega con él» te da los comandos.
